03 · Page-by-page design breakdown
Page 1 / Home — hero and discovery
 [IMG ['rId11']]
Home hero, ~00–06 s; two hero tabs and integrated search module.
Hierarchy.  Small role switch “Mentee | Mentor” at top of hero (Mentee active with green underline), oversized three-line title “Empowering Communities Through Mentorship”, an introductory paragraph, and a wide embedded search bar. The right half is mostly airy white space, with subdued geometric background artwork and floating avatar images.
Search module.  Search-by-mentor/language/free text; Categories dropdown; Country dropdown; prominent green SEARCH CTA. Inputs are arranged horizontally with light vertical separators and soft outer shadow.
Observable interaction.  The role switch and search fields are visible but not actively submitted in the footage. To replicate expected behavior, tab choice should switch the hero copy/CTA or audience view; submit should navigate to Mentors with URL-encoded filters. These outcomes are PROPOSED.
Hero design spec.  H1 roughly 52–58px desktop; explanatory paragraph 15–16px; left content column about 540px; search bar width about 950–1000px; green active indicator, subtle patterned background. Keep visual whitespace intentionally large.
Page 1 / Home — workflow strip
 [IMG ['rId13']]
Three-step onboarding cards, ~07–09 s.
Composition.  Centered “Workflow” eyebrow, two-line heading, three evenly spaced feature cards. Icons are mint/green stylized people and actions. Middle card has subtle raised/shadowed emphasis (possibly hover).
Card copy.  Create Account → Complete your profile → Connect Mentors. Each uses centered icon, bold title, two-line support text. These are informational blocks, not proof that onboarding transitions were exercised.
Page 1 / Home — category browser
 [IMG ['rId14']]
Category grid, ~09–11 s; four columns of tiles.
Section background.  Very light grey. Centered “Categories” eyebrow and heading “Browse Mentors by Categories”. Grid of 12 cards in four columns × three rows on desktop, each featuring a tiny thin-line green icon, category title and live mentor count.
Observed categories.  Software Engineering (6), Marketing (1), Product Management (1), Design (0), Data Science (1), Content Writing (3), Leadership (1), Management (3), Startup (0), Career (9), Cloud Technology (0), CRM and ERP (0). Counts are snapshots, not constants.
Behavior to build.  Category tile navigates to a filtered mentor directory (PROPOSED, not clicked). Zero-count categories can remain selectable, displaying an empty state rather than disappearing.

Some are not fully visible in a single frame; copy is cross-checked against the public home page.

Assets.  Reuse a logo asset, category icons/line SVGs, illustration icons, mentor profile photos and country flags. In absence of source assets, replace with consistent vector equivalents; do not use random stock people for identifiable mentor profiles.

05 · Data model and API plan
Implementation boundary  The recording does not expose the live service API, database, framework, request schema, authentication design, or third-party providers. Everything in this section is a PROPOSED replacement API for a working replica; not reverse-engineered private endpoints.
Frontend / backend stack
Frontend.  Next.js + TypeScript, Tailwind CSS (or CSS Modules), React Hook Form + Zod, TanStack Query, Lucide icons, responsive image optimization. Alternative: Vite + React Router for purely client-rendered replica.
Backend.  FastAPI + Pydantic + SQLAlchemy + PostgreSQL. JWT session/cookie strategy or server sessions, object storage (S3-compatible) for mentor/blog media, SMTP/provider for contact and verification email.
Infrastructure.  Deploy frontend to Vercel or another CDN; backend to managed container/app host; PostgreSQL managed database; HTTPS everywhere; CDN-cached media; logging and basic error monitoring.

Backend correctness / privacy / security
Jobs endpoint must return 401/403 to unauthorized requests; front-end red gate is purely presentation.
Validate all filter parameters and contact fields on server. Parameterized queries prevent SQL injection.
Throttle login/contact routes, include spam protection and CSRF defenses if using cookie sessions.
Store password hashes with modern memory-hard hash, never plaintext; rotate session credentials and log sign-in security events.
Mentor profile images and blog images should be optimized and stored as asset URLs, not embedded base64 blobs in directory API.
Never copy personal data, identifiable profiles or copyrighted brand assets from the source site without appropriate authorization.
Show truthful availability and session status; never promise booking success until server confirms.

A11y and interaction quality checklist
Set one H1 per page, use semantic landmarks (header, nav, main, footer) and actual buttons/links.
Provide text labels for all form inputs; avoid placeholder-only labeling.
FAQ uses aria-expanded/aria-controls and Enter/Space; menu must operate without hover.
Preserve visible focus ring. Aim for WCAG AA contrast for body text and interactive controls.
Mentor images get useful alt text or neutral empty alt for decorative images; logo has a text alternative.
Respect prefers-reduced-motion; use skeleton loading with stable heights to prevent layout shift.
Support logical tab order, error text, and aria-live submission feedback.
Performance guidelines
Compress and resize mentor images, include width/height, lazy-load below-the-fold cards.
Use query caching and pagination for directory; avoid downloading every mentor on initial load.
Prerender static pages (FAQs, marketing, legal) where practical, and cache public listing APIs.
Keep external chat/accessibility widgets opt-in until script ownership and performance are confirmed.
Measure Core Web Vitals in a real browser; target fast LCP and minimal layout shift on Home and Mentors.
Recommended build sequence
Build tokens, font, header, footer and active-route navigation. Validate Home hero proportions first.
Create static responsive page shells: Home, Mentors, Sessions, Blogs, Jobs, FAQs, Contact.
Implement backend models + seed content + public read endpoints.
Connect mentor search, category links, sessions and blog search to real API responses.
Implement FAQ accordion and contact submission with validation.
Add authentication, Jobs authorization, then deeper mentor/booking flows.
Perform screenshot regression at the same desktop viewport as the supplied recording.
